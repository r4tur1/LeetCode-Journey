## Repository structure

Each problem is kept in its own numbered directory so the archive stays searchable and easy to extend.

```text
.
├── 1-two-sum/
├── 9-palindrome-number/
├── 13-roman-to-integer/
├── 14-longest-common-prefix/
├── 217-contains-duplicate/
└── README.md
```

Each solution directory may include:

- The submitted Python implementation
- The original problem context
- Runtime and memory results
- Notes about the approach and complexity

## Solution standards

Every new solution should aim to be:

1. **Correct** — accepted by LeetCode and checked against edge cases.
2. **Readable** — clear names, focused logic, and minimal noise.
3. **Explainable** — supported by an approach and complexity summary.
4. **Reviewable** — organized so it can be revisited and improved later.
